## 修正①: 別タブ復帰でくるくる & 生成文消失

### 症状

- コンテンツ生成後に別タブへ移動 → 戻ると生成文が消えてローディングが固まる
- スタイリスト一覧・その他10ページでも同様のくるくる発生
- 一括生成ページは影響なし（`useState` ローカル管理のため）

### 根本原因

Supabase JS v2 はタブ復帰時に `visibilitychange` を検知してトークンリフレッシュを実行し、`SIGNED_IN` イベントを再発火する仕様。

`authStore.ts` の `onAuthStateChange` ハンドラが **同一ユーザーかどうかに関わらず無条件で `resetAllStores()` を呼んでいた** ため、以下が発生：
- `useGenerateStore.reset()` → `generatedContent: ""` → 生成文消失
- `useSalonStore.reset()` → `hasFetched: false` → くるくる固定

さらにリスナーの戻り値（`subscription`）を捨てていたため、アンサブスクライブ不可 → 多重登録リスクもあった。

### 修正内容

**`frontend/src/stores/authStore.ts`**

```ts
// モジュールスコープでサブスクリプションを保持
let authSubscription: { unsubscribe: () => void } | null = null;

// initialize() 内
if (authSubscription) {
  authSubscription.unsubscribe(); // 多重登録防止
  authSubscription = null;
}

// SIGNED_IN ハンドラに同一ユーザーチェック追加
if (event === "SIGNED_IN" && session?.user) {
  const currentUserId = get().user?.id;
  if (currentUserId === session.user.id) {
    return; // タブ復帰・トークンリフレッシュはスキップ
  }
  resetAllStores(); // 別ユーザーのログイン時のみ実行
}

authSubscription = subscription; // 戻り値を保持
```

## 修正②: チャット修正画面の "Failed to fetch" エラー

### 症状

- 履歴画面から「修正」ボタンを押すと `"エラー: Failed to fetch"` トーストが出る
- プレビューには既存文章が表示される（最初のAPI呼び出しは成功）

### ChatPage の API 呼び出し構造

```
GET  /api/v1/contents/{id}        ← 成功（プレビュー表示）
POST /api/v1/chat/sessions        ← 成功（セッション作成）
GET  /api/v1/chat/sessions/{id}   ← 500エラー ← ここが問題
```

### 根本原因

`001_initial_schema.sql` の `chat_messages` テーブル定義に `updated_at` カラムが**漏れていた**。

SQLAlchemy の `TimestampMixin` が `updated_at` を定義しているため、クエリ実行時に `SELECT ... updated_at ... FROM chat_messages` が走り、PostgreSQL が `column "updated_at" does not exist` を返し 500 エラー。

レスポンスは `content-type: text/plain` / `content-length: 21`（= "Internal Server Error"）でRailwayエッジから返っており、Railwayログには何も出ないタイプのエラーだった。

### 修正内容

**`frontend/src/pages/ChatPage.tsx`**
3つのAPI呼び出しを個別 try/catch で囲み、どのステップで失敗したか特定できるエラーメッセージに変更。

**`backend/migrations/013_chat_messages_updated_at.sql`**（Supabase本番DB適用済み）
```sql
ALTER TABLE chat_messages ADD COLUMN IF NOT EXISTS updated_at TIMESTAMPTZ DEFAULT NOW();
```
RLSポリシーも `DROP POLICY IF EXISTS` → `CREATE POLICY` パターンで再設定。

※ `CREATE POLICY IF NOT EXISTS` はPostgreSQLで非対応構文なので注意。
